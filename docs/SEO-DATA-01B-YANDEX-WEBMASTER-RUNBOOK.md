# SEO-DATA-01B: локальная диагностика Яндекс Вебмастера

Инструмент читает данные Яндекс Вебмастера для `https://www.masterzabor.by/`
и сохраняет локальный JSON-снимок. Он не меняет сайт, настройки Вебмастера,
Sitemap или индекс и не отправляет страницы на переобход. Используются только
официальный API, Node.js и отдельный OAuth-токен; новые npm-пакеты не нужны.

## Рабочий порядок

**Создание OAuth-приложения и токена — только после review реализации.**
Пока локального `.env.yandex-webmaster.local` нет, `doctor` должен завершаться
безопасной ошибкой, не запрашивая и не показывая токен.

После review и локальной настройки из корня проекта:

```powershell
npm run seo:yandex-webmaster:doctor
npm run seo:yandex-webmaster:snapshot
```

Запускайте `snapshot` только после `PASS` от `doctor`. `doctor` проверяет
токен, точный host, подтверждение прав, доступность данных и Sitemap, затем
выполняет read-only проверки доступа к внешним ссылкам и мониторингу запросов.
Токен и заголовок `Authorization` никогда не выводятся.

`snapshot` скачивает публичный
`https://www.masterzabor.by/sitemap.xml`, берёт уникальные canonical `<loc>`
без фиксированного числа URL и собирает данные host, индексирования,
Sitemap, поисковых запросов и внешних ссылок. Один файл появляется в
`.tmp/seo/yandex-webmaster-snapshot-<UTC>.json`. Папка `.tmp/` исключена
из Git. Снимок может содержать запросы, URL и внешние ссылки; храните его
локально и передавайте только осознанно. Сбой отдельного раздела записывается
в файл как явная ошибка; `dataComplete=false` означает, что все данные
получить не удалось. `complete=true` означает лишь, что каждый
запланированный раздел получил результат или явную ошибку.

## Отдельная локальная конфигурация

После review создайте `.env.yandex-webmaster.local` из
`.env.yandex-webmaster.example` и заполните:

| Переменная | Значение |
| --- | --- |
| `YANDEX_WEBMASTER_TOKEN` | Отдельный **access token** Яндекс OAuth для Вебмастера. |
| `YANDEX_WEBMASTER_HOST_URL` | `https://www.masterzabor.by/` — точный host для проверки. |

Токен хранится **только** в `.env.yandex-webmaster.local`; файл уже
исключён из Git правилом `.env*.local`. Не вставляйте токен в чат,
документацию, `.env.example`, Vercel или production env.
`YANDEX_METRIKA_TOKEN`, GSC credentials и существующие интеграции не
используются и не меняются. `host_id` вручную вводить не нужно: скрипт
получает его из списка hosts API и сверяет с заданным host URL.

### Получение и восстановление токена — после review

Для инструмента требуется отдельное приложение Яндекс OAuth, не приложение
Метрики. Начальная стратегия минимального доступа — **только**
`webmaster:hostinfo`. Общая инструкция Яндекса перечисляет также
`webmaster:verify`, но он не входит в утверждённую read-only модель.
Достаточность одного `webmaster:hostinfo` для *всего* snapshot пока не
доказана: `doctor` проверит разные endpoint'ы с реальным токеном. Если
конкретный endpoint вернёт ошибку прав, не добавляйте `webmaster:verify`
автоматически — сначала сохраните безопасный код ошибки и отдельно
согласуйте изменение scope.

Официальная [инструкция Яндекс OAuth для Вебмастера](https://yandex.ru/dev/webmaster/doc/ru/tasks/how-to-get-oauth)
описывает создание приложения, redirect URI
`https://oauth.yandex.ru/verification_code` и переход по ссылке авторизации
для выдачи токена. Она указывает срок действия токена **6 месяцев**.
`YANDEX_WEBMASTER_TOKEN` — access token, а не Google-подобный refresh token:
автоматического refresh-token flow здесь нет. При истечении срока или отзыве
доступа заново получите токен через авторизацию отдельного Webmaster
приложения и замените только локальное значение
`YANDEX_WEBMASTER_TOKEN`. Затем повторите `doctor`. Не пересылайте токен
исполнителю или в чат.

## Что проверяет doctor

1. Наличие локального env без печати значений.
2. `GET /v4/user`, список hosts и точное соответствие
   `ascii_host_url` или `unicode_host_url` заданному
   `https://www.masterzabor.by/`.
3. Детали выбранного `host_id`: `verified=true`, исходный
   `host_data_status=OK`. Другой host автоматически не подставляется.
4. Обнаруженные Яндексом Sitemap и отдельно Sitemap, добавленные
   пользователем. Если файл обнаружен через `robots.txt`, но не добавлен
   вручную, это отдельная пометка, а не утверждение об отсутствии Sitemap.
5. Read-only scope probes:
   `GET …/links/external/samples?limit=1` и
   `POST …/query-analytics/list` с `limit=1`,
   `text_indicator=QUERY`. Последний POST **только читает**
   фильтрованные данные и не меняет настройки.

`PASS` означает, что эти проверки доступа прошли. Он не гарантирует,
что каждый дополнительный snapshot endpoint будет доступен или вернёт
данные. Ошибки отдельного snapshot endpoint'а сохраняются в JSON.

## Что означает snapshot

- Истории индексирования, количества страниц в поиске и появления/удаления
  страниц запрашиваются за указанные в JSON 28 дней. Индексные и поисковые
  URL-выборки листаются с лимитом API до 50 000 URL; результат отмечается
  как неполный при ошибке или достижении потолка выборки.
- `search-queries/all/history` и `search-queries/popular` используют
  период API по умолчанию — последнюю неделю. Фактически возвращённые
  `date_from`/`date_to` популярных запросов сохраняются. Не считайте
  эти данные автоматически 28- или 90-дневными.
- `query-analytics/list` для `QUERY` и `URL` работает с данными
  **последних двух недель**. Он возвращает показатели
  `IMPRESSIONS`, `CLICKS`, `CTR`, `POSITION`, `DEMAND`, если они доступны.
  `popular_complementary_indicator` — лишь наиболее частотная
  дополнительная связка, а не полный набор пар «запрос × URL».
- Данные внешних ссылок — API-выборка ссылок и история
  `LINKS_TOTAL_COUNT`; не приравнивайте их к Google Links UI.
- Сравнение с текущим Sitemap — строгое совпадение URL. Значения
  `notObservedInSample` и `comparisonUnavailable` **не означают**
  `indexed=false` или постоянное исключение из поиска. У API Яндекса
  здесь нет эквивалента поштучного GSC URL Inspection verdict.

Поля `last_access_date`, `urls_count` и `errors_count` у найденного
Sitemap сохраняются как возвращены API. Отдельную дату обработки или
статус URL скрипт не придумывает.

## Ошибки и ограничения

| Код/ситуация | Что проверить |
| --- | --- |
| `MISSING_LOCAL_ENV`, `MISSING_WEBMASTER_TOKEN` | Локальный файл и отдельный Webmaster access token. Не публикуйте значение. |
| `INVALID_OAUTH_TOKEN`, HTTP 401/403 | Токен истёк, отозван или неверен; перевыпустите его через отдельное приложение и повторите `doctor`. |
| `ACCESS_FORBIDDEN` | Scope или права аккаунта на нужный host; не добавляйте `webmaster:verify` без отдельного решения. |
| `HOST_NOT_UNIQUE_OR_MISSING`, `HOST_NOT_VERIFIED`, `HOST_DATA_NOT_READY` | Точный `www` host, права и `host_data_status` в Вебмастере. |
| `SITEMAP_NOT_DETECTED` | Проверьте точный URL Sitemap и его состояние в интерфейсе Вебмастера. |
| HTTP 429 / `QUOTA_EXCEEDED` | Подождите до сброса квоты; не запускайте snapshot подряд. |
| Отдельный `partial`/`error` | Посмотрите безопасный код ошибки конкретного раздела в JSON; остальные разделы сохранены. |

Официальный [`query-analytics/list`](https://yandex.ru/dev/webmaster/doc/ru/reference/host-query-analytics)
возвращает максимум 500 записей за запрос и документирует ограничение
10 000 запросов в час для мониторинга. Для других методов возможна
суточная квота с `QUOTA_EXCEEDED`; скрипт использует ограниченный
retry/backoff для временных ошибок, но не повторяет исчерпанную
суточную квоту. Официальные [коды ошибок](https://yandex.ru/dev/webmaster/doc/ru/reference/errors)
сохраняются безопасно, без текста ответа, который мог бы раскрыть
служебные данные.

## Граница безопасности

Разрешены только перечисленные в скрипте документированные GET-методы
чтения и один `POST …/query-analytics/list` для чтения аналитики. Скрипт
не вызывает добавление/удаление host, verification, отправку URL или
Sitemap на переобход, добавление/удаление Sitemap, операции с фидами
или изменение настроек.
